# GarmentFlow

Outsourced garments operation management: product planning and color/size variants, procurement, material inventory, vendor production, quality control, finished goods, sales, logistics, accounting and administration.

## Deployment target

Next.js App Router, React, TypeScript, Prisma 6, PostgreSQL (Neon), GitHub and Vercel. Node.js 22.x and Bun are required. The original Bun dependency lock is retained. See [AUDIT.md](AUDIT.md) for the scope of repairs and remaining verification requirements.

## 1. Local preparation

Extract the archive and open its `garmentsflow` folder. Use Node.js 22 and install Bun using its official installation instructions if it is not installed. Create a **new, empty** Neon database and obtain both the pooled and direct connection strings.

```bash
cd garmentsflow
cp .env.example .env
```

Edit `.env`: set `DATABASE_URL` to the pooled Neon connection string, `DIRECT_URL` to the direct connection string, and `AUTH_SECRET` to a random secret generated by `openssl rand -hex 32`. Use the same AUTH_SECRET for a given deployment across restarts; changing it can invalidate encrypted two-factor secrets. Never commit `.env`.

```bash
bun install --frozen-lockfile
npm run db:validate
set -a; source .env; set +a
DATABASE_URL="$DIRECT_URL" npm run db:deploy
```

The migration is for a clean database; it does not import existing SQLite records. Do not run it against an existing production schema without a backup and migration plan.

## 2. Create the initial owner

```bash
read -r -p 'Owner email: ' ADMIN_EMAIL
read -r -s -p 'Owner password (minimum 12 characters): ' ADMIN_PASSWORD; echo
export ADMIN_EMAIL ADMIN_PASSWORD
npm run db:init
unset ADMIN_EMAIL ADMIN_PASSWORD
```

The initializer creates the owner and essential master data without demo transactions. Re-running it will not reset existing credentials. Public owner registration is disabled. Configure locations, exchange rates, opening capital, inventory and vendors before using live operational transactions.

## 3. Validate locally

```bash
npm run typecheck
npm run build
npm start
```

In another terminal:

```bash
curl -fsS http://localhost:3000/api/health
read -r -p 'Test owner email: ' TEST_EMAIL
read -r -s -p 'Test owner password: ' TEST_PASSWORD; echo
export TEST_EMAIL TEST_PASSWORD
npm run test:smoke
unset TEST_EMAIL TEST_PASSWORD
```

Use test data and a separate database for acceptance tests. Do not treat a successful health check as proof that all operational workflows work.

## 4. GitHub

Create an empty GitHub repository named `garmentsflow` (without an initial README), then run:

```bash
git init -b main
git add .
git status --short
git commit -m "Prepare GarmentFlow for PostgreSQL and Vercel deployment"
git remote add origin https://github.com/YOUR_USERNAME/garmentsflow.git
git push -u origin main
```

The included GitHub Actions workflow provisions PostgreSQL 16 and checks schema validation, migrations, schema drift, TypeScript, build and authentication smoke tests. Wait for a green CI run before releasing. Fix any remaining failures before using production data.

## 5. Vercel

Import the GitHub repository into Vercel, choose the Next.js framework, root directory `.` and Node.js 22.x. The `vercel.json` sets the Bun install and build commands. Configure production environment variables:

| Name | Value |
| --- | --- |
| DATABASE_URL | Neon pooled PostgreSQL connection URL with SSL |
| AUTH_SECRET | The generated secret for this deployment |

Use a separate Neon database/branch and secret for preview deployments. Do not expose database or authentication secrets as `NEXT_PUBLIC_*` variables. Database migrations and initial owner setup are deliberately separate from Vercel builds; execute them before deployment. Deploy after CI passes.

Verify `/api/health`, open the home page and log in. Test the product planning, stock, production, QA and financial flows on a staging database before go-live. Document uploads are stored in PostgreSQL and limited to 4 MiB per file.

## Security and release notes

No demo password is supplied. The archive excludes the original local SQLite database, old environment files and generated build files. Location assignments are not an enforced data-isolation boundary. Sales cancellation is disabled pending a complete stock/accounting reversal workflow. Use a trusted owner account until role permissions and full workflows have been acceptance-tested. For the audit limitations, read `AUDIT.md`.
